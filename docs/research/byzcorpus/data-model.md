# ByzCorpus — Προκαταρκτικό μοντέλο δεδομένων και έλεγχοι

[Επισκόπηση](README.md) · [Segmentability pilot](segmentation-pilot.md) · [Roadmap](roadmap.md) · [Απογραφή](../corpus/README.md)

> **Κατάσταση:** υποψήφιο schema v0.0 (σχεδιασμός). Οι ονομασίες πεδίων αποτελούν προτάσεις και θα κλειδώσουν ύστερα από δοκιμή σε πραγματικά αρχεία.

## 1. Ελάχιστες οντότητες

| Οντότητα | Ενδεικτικά πεδία | Σημαντικός περιορισμός |
|---|---|---|
| `work` | `work_id`, τίτλος, συνθέτης/απόδοση, είδος, λειτουργική χρήση | Ένα έργο μπορεί να έχει πολλούς μάρτυρες |
| `witness` | `witness_id`, `work_id`, βιβλιοθήκη/συλλογή, shelfmark, χρονολόγηση, folio/page | Καταγραφή συγκεκριμένης πηγής και αβεβαιότητας |
| `transcription` | `transcription_id`, `witness_id`, format, έκδοση, επιμελητής, file hash | Διατήρηση του πρωτοτύπου και ιστορικού αλλαγών |
| `symbol` | `symbol_id`, transcription, θέση, αρχική νευματική πληροφορία | Η γραφική μονάδα διακρίνεται από το μελωδικό γεγονός |
| `event` | `event_id`, transcription, σειρά, interval/degree, χρόνο, context | Κάθε γεγονός αντιστοιχίζεται στα σύμβολα που το παράγουν |
| `text_alignment` | λέξη, συλλαβή, τονισμός, `event_id` range | Μία συλλαβή μπορεί να αντιστοιχεί σε πολλά γεγονότα |
| `segment_occurrence` | `occurrence_id`, source range, `accepted_boundary_pairs`, status | Εναλλακτικά όρια δηλώνονται ως ολόκληρα νόμιμα ζεύγη |
| `family` / `specification` | `family_id`, scope, διαγνωστικά, exclusions, version | Η οικογένεια είναι μουσικολογική αναλυτική κατηγορία |
| `historical_relation` | source/target passage, relation type, evidence, status | Διακρίνει συν-εξήγηση, συγγένεια και αντιγραφή |
| `rights` | rightsholder, license, permitted uses, evidence URL, review date | Η άδεια ισχύει για το συγκεκριμένο αντικείμενο |

Τα αναγνωριστικά έργων και μαρτύρων είναι διακριτά από τα Cantus IDs και από ονομασίες φακέλων. Η αντιστοίχιση μεταξύ διαφορετικών ονοματοδοσιών ορίζεται ρητά, εφόσον υπάρχουν γνωστά IDs.

## 2. Επισημειώσεις μελωδικών ορίων και πραγματική κάλυψη

Η πρώτη [συγκριτική μελέτη συμφωνίας ειδικών](expert-boundary-pilot.md) προϋποθέτει δομές πέρα από τον κατάλογο μουσικών θέσεων:

| Οντότητα / πεδίο | Ενδεικτικός ρόλος |
|---|---|
| `annotation_task` | group_id, window_id, tradition, level_id, candidate_gap_ids, guide_version |
| `annotation_submission` | task_id, annotator_id, timestamp, submission_status (`complete` / `missing_submission` / `invalid_unreviewed`) |
| `reviewed_gap_mask` | προσωπικό σύνολο εξετασμένων αρχικών gap IDs |
| `gap_decision` | boundary / continuation / abstain με αιτία, σε συγκεκριμένη αναλυτική κλίμακα· κενό χωρίς κατάσταση = `unreviewed` και άκυρη υποβολή |
| `technical_mask` | κενά ανεπίδεκτα αξιόπιστης τεχνικής ανάγνωσης |
| `text_stratum` | end_of_word / within_word_syllable_end / inside_syllable / unaligned |
| `source_window` | αναγνωριστικό μάρτυρα, εύρος αρχικών γεγονότων και 16+96+16 context |
| `pilot_registry` | όλες οι προεπιλεγμένες ομάδες, και όσες μένουν χωρίς υποβολή |
| `annotation_analysis` | προτιμώμενη πλήρης ανάλυση και διακριτές εναλλακτικές ανά επίπεδο |

Το σχήμα διατηρεί την ακολουθία των 128 πρωτογενών γεγονότων (δείκτες 0–127) και τα **95 αρχικά εσωτερικά gaps** του κέντρου των 96 γεγονότων (16–111). Σύμβαση: το `gap_id = j` βρίσκεται ανάμεσα στα γεγονότα `j−1` και `j`· επιλέξιμα είναι τα 17–111. Δεν συγκολλά τμήματα που χωρίζονται από εκκρεμή ή τεχνικά μη διαθέσιμα κενά. Οι σιωπηρές κενές τιμές δεν μετατρέπονται σε αρνητικές κρίσεις. Όλα τα πεδία βρίσκονται στο στάδιο `schema draft`.

## 3. Κανονική συμβολική αναπαράσταση

Προτείνεται μία **ακολουθία ατομικών μελωδικών γεγονότων** ως κοινός άξονας. Για κάθε γεγονός φυλάσσονται προέλευση και αντιστοίχιση προς τα γραφικά σημεία. Οι προσαρμογές για pitch-only, interval-only, neume-group και textual feature streams παράγονται ως ελεγχόμενες προβολές.

Ως **προτεινόμενη διαγνωστική προβολή φθογγικών γεγονότων** ορίζεται η `π_note`. Στόχος της είναι να προσεγγίσει τα πεδία εισόδου του Mavromatis (2005, Παράρτημα Α, σσ. 101–102· Πίν. C.1, σ. 161): κώδικας τονισμού συλλαβής, **διάρκεια του προηγούμενου φθόγγου**, διατονικό διάστημα, διατονική βαθμίδα/όνομα φθόγγου και μικροδιαστηματική συνιστώσα ύψους. Η προβολή παραλείπει ως άμεσα πεδία την ταυτότητα νεύματος, τα ποιοτικά σημάδια, τις μαρτυρίες, τις φθορές και τις νευματικές ομάδες. Για να χαρακτηριστεί ισοδύναμη με την είσοδο του Mavromatis, απαιτείται έλεγχος της κωδικοποίησης τονισμού, των μονάδων διάρκειας και ύψους, της κατεύθυνσης του διαστήματος και των αρχικών γεγονότων. Η εξαγωγή προδιαγράφεται ως ντετερμινιστική **αφού** έχει επαληθευτεί η συμβολική μεταγραφή και η αντιστοίχιση νευμάτων–φθόγγων· η σχετική υλοποίηση και επικύρωση αποτελούν επόμενο βήμα. Για κάθε προβολή καταγράφεται η πληροφορία που παραλείπεται και κάθε εξάρτηση από ερμηνεία ή εξήγηση.

Η ομαδοποίηση `u3=f_group(N)` της Μ1 εξαρτάται αποκλειστικά από το σημειογραφικό στρώμα `N`. Το υπό ανάπτυξη toolkit δεν αλλάζει αυτή την προδιαγραφή ούτε εισάγει οικογενειακές ετικέτες στον ορισμό του token.

**Απαιτούμενοι έλεγχοι:**
- Αναγνωσιμότητα και επικύρωση της αρχικής μορφής (π.χ. `.byz` όπου είναι διαθέσιμο).
- Σταθερή σειρά γεγονότων και αντιστρεπτή αντιστοίχιση προς τις αρχικές γραφικές περιοχές στον βαθμό που το επιτρέπει το format.
- Ρητή καταγραφή απώλειας πληροφορίας σε εξαγωγές προς pitch/interval/MusicXML.
- Δυνατότητα ανακατασκευής των πρωτογενών γεγονότων και επιθεώρησης κάθε ασυμφωνίας.
- Διακριτά `known`, `unknown`, `not_applicable`, `unverified` για πεδία και επισημειώσεις.
- Συμμόρφωση με τον έλεγχο κοινών έργων, πηγών και ιστορικών σχέσεων πριν από train/test splits.

## 4. Ένα μικρό *σχηματικό* παράδειγμα

Το παρακάτω JSON παρουσιάζει πεδία προς σχεδιασμό. **Δεν αναπαριστά ιστορικό μάρτυρα ή πραγματική επισημείωση.**

```json
{
  "work_id": "DEMO_WORK",
  "witness_id": "DEMO_WITNESS",
  "transcription_id": "DEMO_TRANSCRIPTION",
  "source_format": "byz",
  "rights_status": "to_be_verified",
  "events": [
    {"event_id": "e001", "index": 0, "symbol_refs": ["s001"]},
    {"event_id": "e002", "index": 1, "symbol_refs": ["s002"]}
  ],
  "annotations": [],
  "annotation_status": "not_started"
}
```

## 5. Διαχείριση πηγών, αδειών και ποιότητας

Οι καταλογογραφικές πληροφορίες της [απογραφής Gheorghiță](../corpus/README.md) διατηρούν το αρχικό `OCR_DRAFT` ή την επαληθευμένη κατάστασή τους· η μεταφορά τους στο ByzCorpus δεν αλλάζει το καθεστώς επαλήθευσης.

Για κάθε έργο πρέπει να ελέγχεται χωριστά: πρόσβαση στην ιστορική πηγή, δικαίωμα δημοσίευσης εικόνας, δικαίωμα αναδημοσίευσης της συγκεκριμένης μεταγραφής, δικαίωμα διάθεσης παραγόμενου συμβολικού αρχείου, όροι χρήσης λογισμικού και απαίτηση απόδοσης.

Η αδειοδότηση του toolkit, του schema και κάθε δημοσιευμένης έκδοσης δεδομένων αποφασίζεται χωριστά. Δεν γίνεται υπόθεση ότι η ανοικτή πρόσβαση μιας εικόνας συνεπάγεται άδεια αναδημοσίευσης όλων των παράγωγων δεδομένων.

## 6. Διαλειτουργικότητα

Η σχεδίαση αξιολογεί τις αρχές του CantusCorpus/PyCantus (σταθερή οντολογία, εύκολη εξαγωγή, provenance και reproducibility). Η συμβατότητα αποτελεί στόχο προς έλεγχο, με adapters όπου είναι πρακτικό, και με ειδική διατήρηση των βυζαντινών γνωρισμάτων. Δεν έχει ληφθεί απόφαση για άμεση εξάρτηση από το PyCantus.

**Επόμενη απόφαση:** οριστικοποίηση `schema v0.1` μετά από επιτυχή εισαγωγή πραγματικών, επιλέξιμων αρχείων Neanes και αξιολόγηση των πληροφοριών που χάνονται ή μετασχηματίζονται.
